OpenWeights / iOS

Open-weight AI.
On your iPhone.

OpenWeights is an experimental iPhone app for running open-weight language models locally. Find compatible models on Hugging Face, download or import weights, and chat on your own device.

Built by Experimental Machines with SwiftUI, llama.cpp, MLX and ExecuTorch.

On-device inference · Measured 7 October 2026

CPU and Metal
on iPhone 16.

Five open-weight models. The same model bytes on each backend. Six-turn conversations that measure how chat feels as the history grows.

Metal started answering sooner and streamed faster in every tested model. LFM2.5 led streaming speed. Gemma started fastest, but often missed the requested reply format.

03 / Method & boundaries

What we measured

M1 / First text
Seconds until the first text callback, including prompt preparation and detokenization. Median across eligible turns. Lower is faster.
M2 / Streaming
Generated tokens per second after generation begins. Replies shorter than eight tokens are excluded. Tokens are not equivalent to words across model tokenizers.
M3 / Process footprint
Whole-process memory sampled every 50 ms, including loading. Median of each wholly nominal conversation's maximum. This is not total CPU-plus-GPU device memory.
M4 / Factual recall
Correct/scorable probes at turns 3, 5 and 6. Strict reply format is scored separately. Three repeats of one conversation do not measure general model intelligence.

A synthetic workshop conversation

The fixture introduces four facts: Birch, Porto, 620 credits and vegan. Later turns add repeated logistics text and request fact recall. The longest recorded prompt was 1,594 tokens. Recall uses messages still inside the context window, not persistent memory beyond it.

Matched within each model

CPU and Metal use identical pinned GGUF bytes, the native chat template, retained prefix cache, greedy decoding, thinking disabled, a 2,048-token context and a 64-token reply cap. Qwen3 1.7B uses Q8_0. The other four models use Q4_K_M.

Temperature affects the headline

Only successful complete conversations contribute data. A timing or recall sample must start and end at nominal thermal state. Memory requires all six turns to stay nominal. All 90 raw recall probes were correct. After thermal exclusions, 82/82 eligible probes were correct. Gemma passed only 3/9 strict-format probes per backend.

Device and build

The personal iPhone 16 (iPhone17,3) ran iOS 26.6.2 build 23G90, with Low Power Mode off. Readiness was confirmed as unlocked, unplugged, cool and at least 60% charged. The signed Release build used Xcode 26.2 build 17C52, SDK 26.2 and llama.cpp commit b2e5e9b28b2484fbf94b543432ece638996a8b97. The five-model batch completed in 33.8 minutes including launches, cache verification and cooling. Downloads were separate.

Read these as engineering observations

Unequal thermal coverage can affect pooled medians. Low Metal process footprints do not prove lower total physical-memory use. We did not measure battery use or energy. Android runs used different workloads and settings, and historical artifact byte identity is unverified. These results support neither a controlled Android-versus-iOS claim nor an intelligence leaderboard. They do not establish that the iOS app is release-ready.

05 / Reproduce & inspect

The numbers are downloadable

The public observations contain every measured turn, including thermal exclusions, generated replies, format outcomes and source-report hashes. Device identifiers, host paths, signing material and private archive locations are omitted.

All 228 turn observations (JSON)Exact six-turn workloadModel revisions & hashesDevice & cohort metadataMeasured native source snapshotPublic file checksums

Recalculate the published tables

Download the reproduction bundle, extract it and run the command below. Python 3.9 or later is sufficient, with no third-party packages or network access. It recomputes the medians, exclusions and frozen factual scores and checks every published summary and turn-table value.

python3 reproduce.py

Full signed test bundles and provider logs remain in private storage. The public export is sufficient to audit the reported aggregates, with exact measured native source inputs available separately. A new native run requires the model files, pinned native dependency and an appropriately signed iPhone build.
